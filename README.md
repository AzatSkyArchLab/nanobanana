# nano banana

**Живая версия: <https://azatskyarchlab.github.io/nanobanana/>**

Мастерская для генерации изображений по референсам через
[OpenRouter](https://openrouter.ai): промпт, до 14 референсов, история с ценами,
итерации «результат → новый референс».

Статическая страница без сборки: те же файлы работают и с диска, и с GitHub Pages.

## Запуск

```bash
cd ~/Проекты/nanobanana && python3 -m http.server 8000
```

Открыть <http://localhost:8000>, вставить ключ OpenRouter в диалоге при первом входе.

Просто открыть `index.html` двойным кликом нельзя — ES-модули требуют `http://`.

## Ключ

Ключ живёт в `localStorage` браузера и уходит напрямую в `openrouter.ai`.
В репозиторий он не попадает, серверной части нет вообще: у OpenRouter открытый
CORS, браузер ходит в API сам.

**Ограничение, о котором стоит помнить.** Пока страницей пользуешься только ты,
свой ключ в браузере — нормально. Если страница станет публичным сервисом,
ключ туда класть нельзя: его вытащит любой посетитель. Тогда нужен прокси
(Cloudflare Worker с ключом на сервере и лимитами на запросы), а в приложении
меняется одно поле — «Базовый URL» в настройках. Весь сетевой код изолирован
в [`js/api.js`](js/api.js) именно ради этого.

## Кисть: локальная правка

Кнопка «Исправить кистью» в просмотрщике результата и карандаш на миниатюре
референса открывают редактор: закрашиваешь область, пишешь, что там должно быть.

Настоящей маски в Images API нет ни у одной из моделей (ни `mask`, ни `inpaint`),
поэтому область передаётся визуально — модель получает две картинки, оригинал
и его копию с пурпурной заливкой поверх нужного места, плюс инструкцию править
только помеченное. Для Gemini это родной способ, проверено: пурпур в результат
не просачивается.

Цветов пять: пурпурный, голубой, зелёный, жёлтый, синий. Можно закрасить
несколько областей разными цветами и ссылаться на них в тексте по отдельности —
«пурпурное замени на дерево, голубое убери». Промпт собирается автоматически
и перечисляет модели только те цвета, которыми действительно закрашено; названия
идут по-английски и по-русски, так что писать можно на любом. Штрих нового цвета
вытесняет старый: пиксель принадлежит ровно одному цвету, смеси не возникает.

Модель всё равно перерисовывает кадр целиком, поэтому по умолчанию результат
склеивается с оригиналом по той же маске с растушёвкой шва — **за пределами
закраски пиксели остаются побитово прежними**. На живой правке менялось 4.78%
кадра, все — внутри закрашенного прямоугольника. Галочку «оставить остальное
нетронутым» стоит снять, если правка должна выходить за границу выделения
(тень от нового объекта, изменение формы).

**Совмещение перед склейкой.** Модель возвращает не попиксельно совпадающий
кадр: композиция уезжает на проценты. Вклеенный как есть результат давал
задвоение — контур из нового кадра ложился рядом с контуром из старого.
Поэтому [`js/align.js`](js/align.js) подбирает сдвиг и масштаб, при которых
результат лучше всего садится на оригинал, сравнивая только то, что **вне**
маски. Поиск двухступенчатый: грубый по семи масштабам на 64 px, затем
уточнение сдвига на 256 px. На проверке с заранее известным уходом кадра
масштаб определился точно, сдвиг с погрешностью 0.7 px, невязка упала в 7.5 раза.

Закрашивать нужно целиком: незакрашенный остаток объекта сохранится как есть.

**Приказ в промпте обязателен.** Один раз он был потерян при переходе на палитру:
осталось безвольное «Instructions: …» посреди списка запретов («ничего не меняй,
рамку сохрани, метки не рисуй»), и модель начала возвращать исходник нетронутым.
Со склейкой это давало кадр, побитово равный входу, — снаружи выглядело как
«приложение ничего не делает». Поэтому в каркасе всегда стоит `Edit image 1:
change ONLY the region covered by the overlay — …` ДО запретов и остаётся
единственным повелительным глаголом.

Чтобы такое больше не пряталось, после ответа считается средняя разница канала
внутри маски. Ниже 4 из 255 (шум пережатия) правка объявляется неприменившейся:
окно кисти остаётся открытым с сохранённой маской, оплаченный результат всё
равно уходит в историю.

## Когда модель возвращает референс

Gemini отвечает копией приложенной картинки, если промпт её ОПИСЫВАЕТ, а не
говорит, что с ней сделать. «Оранжевый круг с треугольником» — просьба вернуть
то же самое; «помести логотип с референса на белую керамическую кружку на
бетонном столе» — задание. Это поведение модели, а не приложения: проверено
повторением известного удачного запроса, код запроса не менялся с первого дня.

Приложение больше не выдаёт копию за результат. После генерации с референсами
считается средняя разница канала с первым из них: ниже 6 из 255 в статусе
появляется предупреждение и напоминание про формулировку. Разделение уверенное —
настоящая генерация против своего же референса даёт 91, копия 0.

## Модели

Список, допустимые пропорции, разрешения и лимит референсов подтягиваются из
`/api/v1/images/models` — новые модели появятся в выпадающем списке сами.

| Модель | Референсов | ~цена за картинку 1–2K |
|---|---|---|
| Nano Banana 2 (`google/gemini-3.1-flash-image`) | 14 | ~$0.07 |
| Nano Banana Pro (`google/gemini-3-pro-image`) | 14 | ~$0.13 |
| Nano Banana 2 Lite (`google/gemini-3.1-flash-lite-image`) | 14 | ~$0.03 |
| Nano Banana (`google/gemini-2.5-flash-image`) | 3 | ~$0.04 |

В списке есть и не-Gemini модели. Отдельно стоит знать про `recraft/*-vector`:
они отдают не растр, а **SVG** — редактируемые кривые, полезно для логотипов
и иконок. Такой результат показывается и скачивается как `.svg`, а при отправке
обратно в референсы или в кисть автоматически растеризуется: `createImageBitmap`
в браузере SVG не декодирует.

Цены до запуска — оценка по прайсу провайдера. Фактическая стоимость приходит
в `usage.cost` и пишется в историю; после первых запусков оценка заменяется
средним по факту для этой модели и разрешения.

У Gemini `n` всегда равно 1: несколько вариантов — это несколько запросов.

## Что где

| Файл | Ответственность |
|---|---|
| `js/api.js` | Единственный слой, ходящий в сеть. Базовый URL, ключ, разбор ошибок |
| `js/db.js` | История в IndexedDB (картинки — Blob, не base64) |
| `js/images.js` | Референсы: чтение файлов, ужатие до 1536 px, скачивание |
| `js/app.js` | UI и состояние |

## Горячие клавиши

- `⌘V` в любом месте страницы — вставить картинку из буфера в референсы
- `⌘Enter` в поле промпта — запустить генерацию

## Другая машина

Открыть <https://azatskyarchlab.github.io/nanobanana/> и вставить ключ — больше
ничего ставить не нужно, ни на Windows, ни где-либо ещё. Ключ у каждого браузера
свой: `localStorage` привязан к origin и к машине.

**История не переезжает.** Она лежит в IndexedDB браузера, поэтому на каждой
машине свой список генераций — даже на одном и том же URL.

## Деплой

Pages уже включены на ветке `main`, папка `/`. Сборки нет, Actions не нужен,
но **перед пушем нужно проштамповать версию**:

```bash
./stamp.sh && git commit -am deploy && git push
```

Зачем: GitHub Pages отдаёт и HTML, и JS с `cache-control: max-age=600`. Десять
минут браузер берёт файлы из кеша, не спрашивая сервер, и способен склеить
свежий `index.html` со старым `app.js` — получается неработающая мешанина
версий. `stamp.sh` меняет `js/app.js?v=…`, а эта версия протаскивается во все
импорты (см. шапку [`js/app.js`](js/app.js)), так что подмешать старый модуль
уже нельзя. Номер загруженной сборки виден в диалоге «Ключ и доступ».

Репозиторий публичный: Pages из приватного репозитория требуют платного GitHub Pro.
Секретов в коде нет — ключ живёт только в браузере, так что публичность кода
на баланс не влияет.
